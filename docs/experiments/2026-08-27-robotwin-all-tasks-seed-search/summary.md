# RoboTwin 全任务高成功率 Seed 搜索阶段总结

## 阶段结论

本阶段已经完成。RoboTwin 的 50 个评测任务均已形成 clean 与 random 两阶段的成功 seed 清单；每个任务、每个阶段各选取 10 个环境 seed，每个入选 seed 都先通过专家规划，并在固定策略采样 seed `42` 下达到连续 5/5 次策略 rollout 成功。全部清单已复制到稳定实验目录的 `successful-seeds/`，原始运行产物仍保留在 `evaluate_results/`。

初次独立测试后，对成功率严格低于 90% 的 13 个任务又按同一协议完成重搜，13 份最终清单均已替换同名稳定归档并分别完成新测试。
至此 50/50 个任务均完成搜索归档和独立测试；大多数任务达到至少 90%，共 40/50（80%），其中 22/50 达到 100%。统一测试结果为
921/1000（92.10%）。

本次针对更换驱动后重新测试的 6 个任务，最终有效运行全部为 `completed`、exit code `0`。更换驱动后没有再次出现此前的 native worker `-11` 或 `-6` 崩溃；但最初运行仍暴露出一个独立于驱动的问题：seed 搜索脚本为专家检查和策略 rollout 创建了不同的任务实例，导致三个任务在 `play_once()` 中建立的派生属性丢失。对任务实例生命周期做最小修复后，三个受影响任务也全部正常完成。

- random：457/500（91.40%）；

- 严格低于 90%：10/50 个任务。

搜索阶段的 5/5 是清单入选条件，不等于跨进程独立测试必然复现；例如最后完成的 `open_microwave` 新清单在独立测试中为 14/20。
50 个任务的逐项结果和失败分类见[全任务验证总结](../2026-08-29-robotwin-all-tasks-seed-validation/summary.md)。

## 问题、修复与验证

原服务器上的失败现象包含 native worker `-11`、`-6` 退出以及停滞。更换至驱动 `570.211.01` 后，本轮没有再次出现这些 native 崩溃，说明驱动或底层运行环境与旧异常相关，但这不是全部根因。

新驱动下首次运行 `open_laptop`、`place_object_scale` 和 `put_object_cabinet` 时，专家可行候选在策略 rollout 首步稳定缺少 `arm_tag` 或 `origin_z`。逐候选记录证明这不是全局调度器漏传参数，也不是这三个任务的原始实现缺陷，而是 seed 搜索脚本没有沿用官方 evaluator 的任务实例生命周期。旧脚本在专家检查后销毁任务实例，再为每次 rollout 新建实例，因此丢失 `play_once()` 设置的派生状态。

修复仅让同一候选的专家检查和全部 rollout 复用同一个任务实例；每次仍重新执行场景 setup、模型 reset 和环境关闭。没有修改任务专用属性、环境 seed 序列、策略 seed、重复次数、5/5 筛选标准、指令或输出结构。聚焦内存测试、静态编译检查和随后的三项完整 GPU 搜索均通过。

旧队列中三个 `failed/143` 是按用户指示停止确定性无效搜索产生的人工终止记录，不是本阶段最终失败。旧代码产生的部分结果没有归档，也没有用于最终成功 seed 清单。

## 适用范围与限制

这些清单证明的是：在发布权重、指定 clean/random 配置、固定策略采样 seed `42` 和当前运行环境下，入选环境 seed 能连续完成 5/5 次 rollout。它们适合本项目后续固定 seed 的可复现评测，但不能直接外推为不同策略采样 seed、更多随机扰动或其他驱动与依赖组合下的同等成功率。若需要覆盖这些变化，应作为新的实验项目单独复测。
